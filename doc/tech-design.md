## 2. 总体架构

采用**模块化单体（Modular Monolith）+ 前后端分离**，而非微服务：

```
                    ┌──────────── Nginx（HTTPS / 静态资源 / 反向代理）────────────┐
   浏览器（桌面）/ H5 │                                                          │
                    └───────────────┬──────────────────────┬───────────────────┘
                                    │ /api/v1/**           │ /assets/**、/print/**
                        ┌───────────▼───────────┐   ┌──────▼──────────┐
                        │  应用服务（单体）      │   │ 静态资源（本地） │
                        │  接入层：网关/鉴权/    │   └─────────────────┘
                        │  数据域过滤/幂等/限流  │
                        │  领域层：13 个模块     │
                        │  基础设施：ORM/事务/   │
                        │  调度/邮件/文件/模板   │
                        └───┬───────────┬───────┘
                            │           │
                 ┌──────────▼──┐   ┌────▼──────────┐   ┌──────────────┐
                 │ MySQL 8.0   │   │ Redis 7       │   │ 本地文件存储  │
                 │ 27 张表     │   │ 会话/限流/锁  │   │ 附件/签名图   │
                 └─────────────┘   └───────────────┘   └──────────────┘
```

**为什么不是微服务**：300 用户、30 TPS 的体量用微服务只会带来分布式事务、链路追踪与运维成本；而 PRD 的复杂度集中在**领域规则**（状态机、闸门、快照）而非吞吐。模块化单体保留清晰边界（下文第 4 节的包结构即模块边界），未来任一模块可独立拆分。

**为什么保留 Redis**：会话（多设备上限与踢出）、限流与幂等键、定时任务的分布式锁。若客户环境禁止 Redis，可降级为「进程内 Caffeine + 数据库会话表」，但会牺牲重启后的会话连续性。

## 3. 技术选型

### 3.1 推荐组合（主方案）

| 层次 | 选型 | 版本 | 选型理由 |
| --- | --- | --- | --- |
| 语言/运行时 | **Java（LTS）** | 17 或 21 | 集团类企业内部系统的主流栈，招人与外包接续成本最低；生态完备 |
| 后端框架 | **Spring Boot** | 3.2.x | 事务、调度、邮件、校验、安全一站式；私有化部署资料最多 |
| ORM | **MyBatis-Plus** | 3.5.x | `data-model.md` 已给出完整 DDL 与伪 SQL（数据域过滤靠 SQL 拼装），MyBatis 的 SQL 可控性优于 JPA |
| 数据库 | **MySQL** | 8.0.x | `data-model.md` 以 MySQL 为准（附录另有 PG 差异说明）；触发器可实现「只追加」不可篡改约束 |
| 缓存/会话 | **Redis** | 7.x | 会话注册表（`sys_user_session` + Redis）、限流、幂等、调度锁 |
| 前端 | **Vue 3 + TypeScript + Vite** | Vue 3.4 / Vite 5 | 企业后台习惯栈，配合 Element Plus 可快速落地高密度表格；构建产物为纯静态，符合「无公网依赖」 |
| UI 组件 | **Element Plus** | 2.x | 表格/表单/日期/抽屉齐备；**定制主题对齐 `DESIGN.md` 令牌**（色值、字号、行高、圆角全部走令牌） |
| 反向代理 | **Nginx** | 1.24+ | HTTPS 终结、静态资源、A4 打印页面路由、上传体积限制 |
| 容器化 | **Docker + Docker Compose** | 24+ | 单机私有化的最小运维面；离线镜像包交付 |
| 构建依赖 | Maven（离线仓库）/ npm（离线镜像） | — | **REQ-NFR-001**：交付时打包 `~/.m2` 与 node_modules 或私服 |
| 打印 | 服务端 HTML 模板 + CSS `@page A4` + 浏览器打印 | — | 与 `DESIGN.print-a4.html` 同源；无需额外排版引擎 |

### 3.2 备选方案与切换代价（供评审取舍）

| 若团队/客户倾向 | 替换内容 | 代价 |
| --- | --- | --- |
| .NET 技术栈 | ASP.NET Core 8 + EF Core/Dapper + Razor/Vue | 后端重写；DDL 与设计文档不受影响 |
| Node.js 技术栈 | NestJS + Prisma/TypeORM | 长事务与调度生态弱于 Java，异步任务需自建 |

## 5. 关键设计

### 5.1 流程引擎：三层模型

| 层 | 表 | 语义 |
| --- | --- | --- |
| 定义 | `flow_template` + `flow_node` | 模板版本 + 7 节点定义（`node_code` 见 `enums.md` §2；⑦ `archive_register` 默认「仅登记不审批」，`decision_mode = NULL` 且不计入时长/效率统计） |
| 实例 | `flow_instance` + `flow_node_instance` | 发起时冻结 `template_version`、`approver_snapshot_json`、`owner_dept_id`（归口恒财务部）；节点实例唯一键 `(instance_id, node_key)` |
| 任务 | `flow_task` | 会签＝同节点多条；一条一人；`origin_assignee_id`（转办/改派）、`delegate_from` + `add_sign_type`（前/后加签） |

**决议算法**（`enums.md` §3）：或签 `any`（任一人通过即节点通过，其余任务 `auto_closed`）；会签 `all`（同意数达阈值，**绝对人数优先**，百分比**向上取整**，`pass_threshold = NULL` 视作「过半」＝ `floor(候选人数/2)+1`；任一人驳回即节点驳回）；依次 `sequential`（按序串行，全通过才通过）。

**状态机与联动**（PRD 7.2）在**引擎层统一实现**：节点驳回 → 同节点其余任务 `auto_closed`、其余节点实例 `cancelled`；实例终态 → 全部在途任务与节点实例收口；跳过（仅事项单②）→ 节点实例 `skipped` + `sys_thread.action = skip` 留痕。

**闸门**：`routing_count` 记录「流转 + 回退」累计（**不含** `back_home`），上限 5；同节点 `returned_count ≤2`；`back_home` 连续 ≤2 由 `flow_routing` 连续记录判定；补件 `supplement_round` 在**请求时占位**，同节点 ≤1、全单 ≤3。

**并发控制**：实例与任务表带 `version` 乐观锁；任务决议在单事务内「校验状态 → 写意见 → 更新节点/实例 → 关闭兄弟任务 → 落轨迹与审计 → 发通知（异步）」。

### 5.2 审批人解析与快照

发起前按 `flow_node.approver_rule` 逐节点解析（9 条规则，见 `enums.md` §2）：组织链派生（本级无负责人则**逐级上溯**）、集团财务部负责人、分公司分管领导、子公司总经理、集团分管领导、董事长、指定人员/角色、发起人自选、协同部门负责人。**候选人集合为空 → 禁止发起**并提示具体节点（REQ-FLOW-012）。

解析结果写入 `approver_snapshot_json` 固化为快照；此后调岗/离职/组织变更**不影响在途单据**。补偿控制：离职前必须清空待办、组织停用前必须清空在途（AC-11/AC-12）；管理员改派为兜底（`reassign`）。

### 5.3 数据域过滤（安全核心）

**原则：唯一入口过滤，禁止各页面自行拼条件。** 实现为三件套：

1. **鉴权阶段**：解析当前用户 → 角色集合 + 数据域集合（`self / dept / company / group_all / group_category`）+ 归口类别 + 组织路径；
2. **SQL 织入**：统一在 Mapper 层织入 `WHERE` 片段（对应 `data-model.md` §7.2 伪 SQL），按数据域取并集：
   - 普通员工：本人发起 ∪ 本人作为审批人（含 `origin_assignee_id`）∪ 抄送人
   - 部门/科室负责人：以上 ∪ `initiator_org_path LIKE :dept_path_prefix`
   - 子公司总经理 / 分公司管理员：`initiator_company_id = :company_id`
   - **集团职能部门（财务部）**：`owner_dept_id = 本部门`（归口类别：资金/合同/印鉴，恒经②）∪ **事项单且 `involve_cost = true`** ∪ `EXISTS(flow_routing WHERE to_dept_id = 本部门)`（流转链）∪ 本部门在途。**「不涉及费用」且未经流转的事项单不可见**
   - 集团分管领导：按业务线映射的类别集合；董事长/系统管理员：无过滤
3. **字段级限制**：金额字段对非财务角色只读、导出仅系统管理员与财务角色（导出留痕）；手机号默认脱敏（`138****8888`）。

**流转可见性**：被流转到的部门对本张单据可见，且**仅限该张**——不得折算为「该部门可见该类别全部单据」（AC-22）。

### 5.4 三态读写与表单模板

- `form_schema_json` 驱动渲染（四类单据共用渲染器），字段定义见 `forms.md` 与 `templates.md`；
- **服务端白名单**控制可写字段：草稿全可写；审批中全只读；待补件仅 `附件` + `补件说明`；**唯一例外**＝印鉴证照单的 `return_status` / `return_date`（发起人与节点⑦可改）；
- 提交时固化 `form_schema_json` 版本号与 `fields_json`（快照），模板后续变更不影响在途单据；
- 金额一律 `DECIMAL(18,2)`，服务端只接受字符串/定点数（**禁止浮点**），上限 `99,999,999,999.99`；
- 附件：单文件 ≤50MB、单次 ≤20、单张 ≤50（含补件）；白名单 15 种（含 `heic` `wps`，需预览降级）；禁止格式 9 种双校验（扩展名 + MIME）；私有化存储、下载必须走鉴权接口。

### 5.5 电子签名与不可篡改

- 前端 Canvas 手写 → PNG → 存本地私有目录；支持个人预存签名一键调用（修改留痕）；
- `flow_signature` **只追加**：`sign_type`（手写/CA）、`signed_at`、设备指纹、IP、`hash`（**SHA-256，覆盖全部业务字段含 CA 预留字段**，字段序固定），重新签署产生新记录；
- 不可篡改在**数据库层**兜底：MySQL 触发器拒绝对 `sys_log` / `flow_signature` / `sys_thread` 的 UPDATE 与 DELETE（迁移 PG 时改用 `REVOKE UPDATE, DELETE`），应用层再做一次只追加校验（AC-20）；
- 保留期：审计与轨迹 ≥10 年、登录日志 1 年（策略可配，配合抽样检索验证）。

### 5.6 通知与定时任务

| 触发 | 站内信 | 邮件 |
| --- | --- | --- |
| 待办产生 / 协同任务产生（每部门一条） | ✅ | ✅ |
| 驳回 / 撤回 | ✅ | ✅ |
| 补件请求 / 补件超时催办 | ✅ | ✅ |
| 节点超时催办（可抄送其上级） | ✅ | ✅ |
| 结果通知（通过 / 终止） | ✅ | ✅（终审通过） |
| 抄送 | 可见但**不产生待办** | — |

邮件发送失败**不阻塞流程**，失败记录可查并重试（本地队列表 + 定时重试）。定时任务：节点超时扫描、补件超时扫描、归档作业、备份触发（均加 Redis 锁，避免多实例重复执行）。

### 5.7 打印渲染

- 版式映射：事项单**统一用子公司内部审批单版式**；合同/资金集团层用集团版式、子公司层用内部审批单；印鉴用印鉴证照版式；
- 服务端渲染 HTML（同源 `DESIGN.md` 打印规格）→ 浏览器打印 A4 / 100% / 无边距；
- **正式打印签名栏一律空栏**（屏幕预览可显示缩略图与时间戳）；常规恰好一页，超长按行分页并在页脚标注「第 X / Y 页」；「公文接收及处理」超出 3 段或流转超过 3 次时**以附页承载**；
- 打印不使用屏幕样式（无色块/圆角/投影），灰度对比度 ≥4.5:1，信息不依赖颜色表达。

## 6. 非功能设计

| 项 | 设计要点 |
| --- | --- |
| 性能 | 待办列表主索引 `(assignee_id, status, created_at)`；实例按单号唯一索引；节点实例按 `(instance_id, status)`；慢查询治理与索引清单（对应 `oa.platform.perf.tuning` 模块）；压测按 30 TPS / 30 分钟 / 错误率 <1% |
| 安全 | Nginx 强制 HTTPS + HSTS；口令 BCrypt(≥10) 或 Argon2id；手机号 AES-256-GCM 落库、密钥轮换（`config/crypto/key-rotation.yml`）；登录失败 5 次锁 15 分钟；越权防护＝统一数据域过滤 + 接口级权限注解 + **越权专项用例**（跨公司、手改 URL、直连接口、未授权导出） |
| 会话 | `sys_user_session` 记录设备与 `token_hash`（唯一键），会话 Cookie `HttpOnly + Secure + SameSite=Lax`；「记住我」7 天；第 4 台登录时对最早会话写 `revoked_at`（**软踢出**，不物理删除） |
| 可用性 | 目标 ≥99.5%（工作日 8:00–20:00）；每日全量备份保留 30 天 + 季度恢复演练（RPO ≤24h、RTO ≤4h）；日志与告警（应用/慢查询/任务失败） |
| 归档 | 满 3 年（阈值可配）转历史库并置只读；历史库仍可按单号检索与预览；归档作业可重跑（幂等） |
| 数据抽取 | 标准化归档结构 + 按月分区文件 + 抽取完成事件（供数仓），一期不开放外部写入 |

## 7. 部署与运维

**拓扑（单机最小集）**：`Nginx` → 应用容器（1–2 实例）→ `MySQL` / `Redis` / 本地文件卷；邮件经内网 SMTP。

| 项 | 做法 |
| --- | --- |
| 交付物 | 离线 Docker 镜像包 + Compose 文件 + 初始化 SQL + 配置模板 + 部署手册 |
| 配置分层 | 环境配置（`config/application.yml`）与**运行期可配置项**（决议模式、阈值、超时、闸门次数、补件上限、强制签名节点、会话与锁定、保留期、导出权限）分离，后者由管理后台维护、不经发版 |
| 升级发布 | 蓝绿或滚动重启；数据库变更走版本化 SQL（Flyway/Liquibase）；**破坏性变更需评审** |
| 备份 | 每日全量 30 天 + 季度恢复演练；归档与备份介质按 Q5 决策落地 |
| 监控 | 应用日志、慢查询日志、任务失败告警、磁盘与连接池水位；可用性统计口径按工作日 8:00–20:00 |
| 安全基线 | 12 项勾选表（HTTPS、口令策略、越权拦截、敏感字段加密、日志留痕、备份、会话与设备、附件鉴权、导出留痕、私有化无公网、最小权限、错误信息不泄露） |

## 8. 数据初始化与迁移

1. **表结构**：执行 `data-model.md` 生成的 27 张表 DDL（含唯一键、CHECK、FK、不可变触发器）；
2. **字典**：执行 `dict-seed.md` 的 8 类 / 37 行幂等 `INSERT`（事项类别、合同类型、用印类型、证照类型、付款方式、集团部门、其他会审部门、归还状态）；

## 10. 技术风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 私有化环境无外网，依赖拉不下来 | 构不出来 | 交付前完成离线仓库（Maven/npm）、镜像包与断网启动演练（AC-33） |
| 数据域过滤漏点 | 越权，最严重 | 统一 Mapper 织入 + 接口级复核 + 逐阶段越权用例；代码评审把「绕过过滤的裸查询」列为阻断项 |
| 引擎状态机分支多（7 节点 + 6 类动作 + 补件） | 挂单/状态不一致 | 状态迁移集中在一处（禁止页面各自实现）；用集成测试覆盖 PRD 7.2 全部联动行；线上提供「状态自检」任务 |
| 触发器实现不可篡改在 MySQL 上的性能 | 写入变慢 | 仅对日志类表加触发器；插入路径无额外索引；压测复核 |
| 打印版式与实单偏差 | 验收不通过 | 设计稿与实单扫描件逐字段核对 + 打印目视用例；版式变更走 `print-mapping` 评审 |
| 文件存储单点 | 附件损坏 | 本地卷 + 每日备份覆盖文件目录；`sha256` 校验；下载鉴权 |
| 单人维护面过大（520 模块） | 交付慢 | 按 13 领域并行分包开发（结构基线已给出边界与 API 契约），每阶段 DoD 卡口 |
