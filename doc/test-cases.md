## 0. 文档说明

### 0.1 用途

本文档把 PRD 第 10 章的 **61 条验收标准**转成**可照着点、可判定**的测试用例（含正常、边界、越权/异常三类），供阶段验收、发版回归与试运行退出判定使用。**每条 AC 至少派生 1 条用例，核心 AC（主干、数据域、闸门、补件、打印、签名）派生 2–6 条。**

### 0.2 本期必须遵守的口径（V0.4）

| # | 口径 | 对本文件的影响 |
| --- | --- | --- |
| 1 | 主干 **7 个审批节点**：①直属部门负责人 ②财务部复核（＝集团归口，只审一次）③分公司分管领导 ④子公司总经理 ⑤集团分管领导 ⑥集团董事长 ⑦归档登记 | 主干用例断言节点顺序必须是 `dept_leader→finance_review→branch_leader→subsidiary_gm→group_leader→chairman→archive_register`，**不得出现第二个归口节点** |
| 2 | 事项类别＝五类**配置项、不参与路由**，集团归口恒为财务部 | 类别用例只验证「可选/可增删/发起后不可改判」与「归口恒为财务部」 |
| 3 | **财务部数据域**＝归口类别（资金/合同/印鉴）＋「涉及费用」事项单＋流转链承接/经过的单据；**「不涉及费用」且未经流转的事项单财务部不可见** | 数据域用例必须用「不涉及费用的事项单」与「经发部承接」两个判别点 |
| 4 | 流转可见性**用经发部验证**（财务部对归口类别本就全可见，无判别力） | 越权/流转可见性用例的验证账号固定为经发部负责人 |
| 5 | 闸门：流转+回退 ≤5、同节点被回退 ≤2、回到本部门连续 ≤2（**不计入总次数**）、补件同节点 ≤1 且全单 ≤3、补件时限 3 个工作日、超时仅催办 | 闸门用例必须出现「第 N 次被拒绝」的临界点与拒绝文案 |
| 6 | 印鉴单「归还状态/归还日期」是三态读写模型的**唯一例外**（审批中仅发起人与节点⑦可改） | 只读用例与该例外用例成对出现 |
| 7 | 金额导出：系统管理员**与财务角色**可导出，非财务角色不可 | 导出用例固定三组账号对比（管理员/财务/普通员工） |
| 8 | 打印：四类单据按版式映射（**事项单统一子公司内部审批单版式**；合同/资金集团层用集团版式），**正式稿签名栏为空栏**，常规恰好一页、超长按行分页 | 打印用例按 6.2 版式映射表逐格核对 |

### 0.3 执行方式（人工 / 自动化）

| 标记 | 含义 | 适用场景 |
| --- | --- | --- |
| **A（自动）** | 可由接口/数据库断言完成，纳入 CI 回归 | 流程状态机、决议模式、闸门计数、数据域过滤、字典、校验类 |
| **M（人工）** | 需要人工观察或无自动化载体 | 打印版式与黑白可读、水印、微信内可用、断网、恢复演练、签字栏空栏 |
| **H（半自动）** | 自动化执行 + 人工确认视觉/文案 | 签名记录、导出留痕、报表口径 |

回归清单（第 7 章）中标注为 `A` 的用例应在每次发版由 CI 全量执行；标注为 `M/H` 的按发版范围抽跑。

### 0.4 环境与数据准备总则

1. **环境**：测试 / 预发两套，均私有化、无公网依赖（字体与静态资源本地化）。测试环境须能**调整系统时钟**（用于补件时限、超时催办、归档阈值、日志保留样本的构造）。
2. **数据**：全部用例复用第 1 章的**组织与人员基线**（一次准备、多次复用）；单条用例的差异数据只在「数据准备」列标注，不重复搭建。
3. **账号**：所有账号口令统一 `Oa@2026test`（符合 8 位含字母数字）；用例中按「基线编号 + 姓名」引用，如「U-07 赵庚」。
4. **前置清理**：每条用例执行前须保证该单据号不存在（`form_data.biz_no` / `flow_instance.biz_no` 双唯一）；跨用例不得共用同一单据号。
5. **数据核对入口**：接口断言通过 `GET /api/flow/instance/{biz_no}` 与 `GET /api/flow/instance/{biz_no}/thread`；库级核对通过只读账号查询 `flow_instance` / `flow_node_instance` / `flow_task` / `flow_routing` / `flow_supplement`（表名以 [`data-model.md`](data-model.md) 为准）。
6. **文档就位情况**：`doc/templates.md`（模板与节点契约）**已就位**，1.3 的节点配置表已与其 §1.1~1.5 对齐；如执行时该文档再次变更（模板版本迭代），以 `templates.md` 为准并逐格核对 1.3（差异按 P1 缺陷处理）。

### 0.5 判定规则

**缺陷分级（引用 PRD 第 11 章「试运行退出条件」第 2 条）**：

| 级别 | 定义 | 处置 |
| --- | --- | --- |
| **P0** | 阻断上线：数据错误、越权、流程不可用 | 立即修复，阻断阶段验收 |
| **P1** | 主流程可用但关键功能异常且无绕行方案 | 阶段验收前必须修复 |
| **P2** | 有绕行方案的缺陷 | 记入待办，可带缺陷过阶段门 |
| **P3** | 体验问题 | 记入待办 |

**用例优先级**（与缺陷分级是两套口径，勿混用）：

| 优先级 | 含义 | 执行要求 |
| --- | --- | --- |
| **P0** | 主干、越权、闸门、数据域、不可篡改 | 每版必跑（进第 7 章回归清单） |
| **P1** | 阶段验收项（对应 AC） | 阶段验收必跑 |
| **P2** | 补充场景、体验与配置类 | 阶段内抽跑 |

**通过判定**：一条用例**全部**预期结果项均通过才记为通过；任一预期项失败即判该用例失败，并按上表定级。断言必须落到具体状态值、字段值、数量或提示文案，**禁止**以「正常」「正确」作为预期。

### 0.6 用例编号与阅读约定

- 编号规则 `TC-<域>-<三位序号>`，域取自 PRD 需求编号域表：`ORG / AUTH / USER / FORM / FLOW / SIGN / MSG / LOG / ADMIN / NFR`。
- 每条用例的「关联 AC / 需求」列**必须写明 AC 编号**（无对应 AC 的写需求编号，如 `REQ-FLOW-018`）。
- 用例表列固定为：`用例编号 | 关联 AC / 需求 | 前置条件 | 操作步骤 | 预期结果 | 优先级 | 所属阶段 | 数据准备`。
- 「所属阶段」按 PRD 第 11 章里程碑与 dev-plan 验收门标注：`一 / 二 / 三 / 四`（专项章节用例沿用其 AC 的阶段）。

### 0.7 断言用枚举速查（写预期结果时直接引用，口径见 `data-model.md`）

| 对象 | 可断言取值 | 说明 |
| --- | --- | --- |
| 实例状态 `flow_instance.status` | `draft` / `approving` / `approved` / `rejected` / `withdrawn`（瞬时态）/ `terminated` | 撤回写入轨迹后**立即回到 draft**，不长期驻留 `withdrawn` |
| 实例子状态 `sub_status` | `NULL` / `pending_supplement`（待补件） | **补件不是驳回**：主状态仍为 `approving` |
| 节点实例状态 | `pending` / `active` / `waiting_supplement` / `approved` / `rejected` / `skipped` / `returned` / `cancelled` | ② 因「不涉及费用」跳过时为 `skipped`；`returned` 为**非终态**（上一节点重审通过后回到 `active`） |
| 任务状态 `flow_task.status` | `pending` / `agreed` / `rejected` / `transferred` / `reassigned` / `added_sign` / `routed` / `rolled_back` / `supplement_requested` / `auto_closed` | 同节点他人已决议、或单据已驳回/撤回/终止 → `auto_closed`；「回退上一节点」→ `rolled_back`；「要求补充材料」→ `supplement_requested`（该任务不可再审批） |
| 节点码 `node_code`（顺序固定） | `dept_leader` → `finance_review` → `branch_leader` → `subsidiary_gm` → `group_leader` → `chairman` → `archive_register` | 共 7 个；**废弃码**：`department` / `group_dept` / `finance` |
| 决议模式 | `any`（或签，默认）/ `all`（会签）/ `sequence`（依次审批） | 阈值 `pass_threshold`：`"2"`（绝对人数）或 `"50%"`（百分比），**绝对人数优先**；`NULL` ＝ 过半 |
| 签名策略 `sign_policy` | `required`（⑤⑥ 默认）/ `optional` / `none` | 强制签名节点不签名不可提交 |
| 流转动作 `flow_routing.action_type` | `route`（流转）/ `return_node`（回退上一节点）/ `back_home`（回到本部门，**不计入** `routing_count`） | `routing_count` 上限 5 |
| 补件状态 `flow_supplement.status` | `pending` / `submitted` / `overdue` / `cancelled` | `supplement_round` 1..3，请求时即占位 |
| 轨迹动作 `sys_thread.action` | `submit` / `approve` / `reject` / `route` / `rollback` / `back_home` / `supplement_request` / `supplement_submit` / `transfer` / `reassign` / `add_sign` / `withdraw` / `terminate` / `skip` / `archive_register` / `cc` | 共 16 值，与 `enums.md` §9 一致；`skip` ＝ 财务节点因不涉及费用被跳过；**废弃值**：`addsign` → `add_sign`、`return_node` → `rollback`、`archive` → `archive_register` |
| 消息类型 `sys_message.msg_type` | `todo` / `rejected` / `withdrawn` / `collaboration`（协同任务产生）/ `timeout` / `supplement`（待补件）/ `result` / `cc` | 一期**无推送通道**，仅站内信与邮件；邮件模板由同一 `msg_type` 决定 |
| 计数列 | `flow_instance.routing_count`（≤5）/ `supplement_count`（≤3）/ `flow_node_instance.returned_count`（≤2）/ `supplement_requested`（≤1） | 闸门断言的四个直接证据 |
| 编号规则 | `biz_no` ＝ `OA-{四位年}-{六位流水}`；组织 `path` ＝ `/1/110/111/112/` | 单号按年重置 |

### 0.8 断言工具与命令样例

以下为本文件「预期结果」列的常用落点，可直接复制执行（`:biz_no` 为该用例准备的单据号）：

| 目的 | 断言方式 | 样例 |
| --- | --- | --- |
| 实例与计数 | 只读库查询 | `SELECT status, sub_status, current_node_seq, routing_count, supplement_count, owner_dept_id FROM flow_instance WHERE biz_no=':biz_no';` |
| 节点顺序 | 只读库查询 | `SELECT node_seq, node_code, status, returned_count, supplement_requested FROM flow_node_instance WHERE instance_id=(SELECT id FROM flow_instance WHERE biz_no=':biz_no') ORDER BY node_seq;` |
| 任务与决议 | 只读库查询 | `SELECT assignee_id, status, opinion, add_sign_type FROM flow_task WHERE instance_id=…;` |
| 流转链闸门 | 只读库查询 | `SELECT seq, action_type, from_dept_id, to_dept_id, reason, status FROM flow_routing WHERE instance_id=… ORDER BY seq;` |
| 补件记录 | 只读库查询 | `SELECT supplement_round, status, deadline, submitted_by FROM flow_supplement WHERE instance_id=…;` |
| 数据域（流转可见性） | 接口 + 列表比对 | `GET /api/flow/instance?keyword=:biz_no`，以经发部账号执行应命中、以非承接部门账号执行应 0 条 |
| 不可篡改 | 数据库直连（有写权限账号） | `UPDATE sys_log SET action='x' WHERE id=1;` → 期望 `ERROR 1644 (45000): sys_log is append-only` |
| 签名哈希 | 应用接口 | `GET /api/sign/{signature_id}/verify` → 期望 `valid`（人为改库后期望 `invalid`） |
| 打印页数与版式 | 浏览器打印预览 + DOM 断言 | 断言页面总高度 ≤297mm 对应像素；断言 `@page` 无缩放；版式 CSS class 与映射表一致 |
